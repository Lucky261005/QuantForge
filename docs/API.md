# API Reference

Full interactive documentation is auto-generated by FastAPI at `/api/v1/docs` (Swagger UI) and
`/api/v1/redoc` — this file is a human-readable map of the surface, not a replacement for it.

Base URL: `http://localhost:8000/api/v1` (direct) or `http://localhost/api/v1` (via Nginx).

## Conventions

- **Versioning**: everything is under `/api/v1`.
- **Auth**: `Authorization: Bearer <access_token>` on every protected endpoint.
- **Pagination**: list endpoints accept `?page=&page_size=` and return
  `{items, total, page, page_size, pages}`.
- **Errors**: RFC 7807-flavored JSON — `{"title": "...", "detail": "...", "status": 404}`.
- **Rate limiting**: Redis-backed, applied to auth and market-data-download endpoints
  (`RATE_LIMIT_AUTH`, `RATE_LIMIT_DATA_DOWNLOAD` in `app/core/config.py`).

## Auth flow

```
POST /auth/register        {email, username, password, full_name?}      -> 201 UserRead
POST /auth/login            {email, password}                            -> TokenPair
GET  /auth/me                Bearer token                                -> UserRead
POST /auth/refresh          {refresh_token}                              -> TokenPair (rotates the old one)
POST /auth/logout           {refresh_token}                              -> revokes it
POST /auth/forgot-password  {email}                                      -> mocked email, logs the token server-side
POST /auth/reset-password   {token, new_password}
POST /auth/send-verification (auth'd)                                    -> mocked email
POST /auth/verify-email     {token}
```

Access tokens expire in 30 minutes (`ACCESS_TOKEN_EXPIRE_MINUTES`); refresh tokens in 7 days and
rotate on every use (the old one is revoked, a new pair is issued) — see `AuthService.refresh_access_token`.

## Market data

```
GET  /assets?page=&page_size=
POST /assets/download   {symbol, start_date, end_date, source?, force_refresh?}
POST /assets/upload?symbol=RELIANCE&asset_type=equity&exchange=NSE&sector=Energy&industry=...&market_cap_cr=...   (multipart CSV file)
GET  /assets/{symbol}/data?start_date=&end_date=
GET  /assets/breadth   -> {advancing, declining, unchanged, new_52w_highs, new_52w_lows, total}
```

`source` is one of `yahoo_finance` (default, auto-resolves NSE/BSE symbols to `.NS`/`.BO`),
`nse_official`, `kite_connect`, `upstox`, `angel_one`, `alpha_vantage`, `polygon`, `csv_upload`.
The `sector`/`industry`/`market_cap_cr` upload params are optional metadata (used by the seed
script and the dashboard's sector-performance/watchlist views). Downloading
an already-cached range returns immediately with `served_from_cache: true` — no external call is made.

## Strategies

```
GET    /strategies/catalog                 -> built-in strategy types + JSON param schemas
POST   /strategies       {name, strategy_type, parameters, description?, is_public?}
GET    /strategies?page=&page_size=
GET    /strategies/{id}
PUT    /strategies/{id}
DELETE /strategies/{id}
```

The catalog is the contract the frontend's Strategy Builder uses to render a dynamic parameter
form — each entry is `{key, label, description, params: [{name, type, default, min, max}]}`.

## Backtests

```
POST   /backtests   {strategy_id, symbols, start_date, end_date, initial_capital?,
                      commission_pct?, slippage_pct?, position_size_pct?,
                      stop_loss_pct?, take_profit_pct?, benchmark_symbol?,
                      charge_model?, brokerage_pct?, risk_free_rate_annual?,
                      rebalance_frequency?}
GET    /backtests?page=&page_size=
GET    /backtests/{id}
GET    /backtests/{id}/status     -> {status, error_message, runtime_seconds}
GET    /backtests/{id}/metrics    -> full risk/return metrics, incl. sharpe/cagr bootstrap
                                      95% CIs (only once status == completed)
GET    /backtests/{id}/equity     -> equity_curve, drawdown_curve, monthly_returns, daily_returns
GET    /backtests/{id}/trades     -> trade blotter
GET    /backtests/{id}/cost-sensitivity  -> same signals rerun at 0x/0.5x/1x/1.5x/2x costs
GET    /backtests/{id}/walk-forward?n_windows=4 -> fixed-parameter performance per rolling window
DELETE /backtests/{id}
```

`rebalance_frequency` is `none` (default), `monthly`, or `quarterly` — only meaningful for
multi-symbol backtests; periodically resets every symbol back to equal weight instead of
letting winners drift to a larger share, with the rebalance's own transaction costs modeled.

`POST /backtests` returns immediately with `status: "pending"` and enqueues the run via Celery
(or executes it synchronously in-process if the broker is unreachable). Poll `/status` — the
frontend does this every 1.5s until `completed` or `failed`.

`charge_model` is one of `flat` (default — the plain `commission_pct`/`slippage_pct` model),
`indian_equity_delivery`, or `indian_equity_intraday`. The latter two compute STT/exchange
transaction charges/SEBI turnover fee/stamp duty/GST from fixed regulator-set rates
(`app/backtesting/charges.py`) — only `brokerage_pct` is user-configurable under those models.

## Analytics

```
POST /analytics/compare              {backtest_ids: [...]}   -> ranked entries + correlation matrix
POST /analytics/optimize-portfolio   {symbols, start_date, end_date, method?, risk_free_rate?}
```

`method` is one of `equal_weight`, `mean_variance`, `risk_parity`, `max_sharpe`, `min_volatility`.

## Watchlists, Research Notes, Portfolio

```
GET/POST/DELETE  /watchlists, /watchlists/{id}/items
GET/POST/PUT/DELETE  /notes
GET  /portfolio
POST /portfolio/transactions   {type: buy|sell|deposit|withdraw, symbol?, quantity?, price?, amount?}
GET  /portfolio/transactions
```

The portfolio is simulated (paper) — `buy`/`sell` price defaults to the latest stored close for
the symbol unless an explicit `price` is supplied; it is not connected to any real brokerage.
